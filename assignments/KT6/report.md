# КТ6. Интеграционное тестирование снизу вверх

**Цель:** Начать с базовых репозиториев, затем подключать API и проверять передачу данных на вышележащий слой.

**Ход тестирования:** Шаг 1: тестирование создания/чтения UserRepository и OrderRepository. Шаг 2: интеграция UserRepository с Users controller. Шаг 3: проверка созданных данных через HTTP GET.

**Набор тестов:** `tests/test_bottom_up.py`

## Сценарии и результаты

| Сценарий | Ожидаемый результат | Итог |
|---|---|---|
| UserRepository: create/get | получен тот же сохраненный пользователь | PASS |
| UserRepository: неизвестный id | возвращается None | PASS |
| OrderRepository: create/get | получен сохраненный заказ | PASS |
| Users controller + repository | GET возвращает данные из внедренного репозитория | PASS |

## Результат

Все 4 bottom-up теста прошли.

## Выявленные проблемы и ограничения

Репозитории изолированы от транспорта, поэтому их поведение проверяется быстро. На этом уровне еще не видны ошибки HTTP-контракта Orders и Users; для них подключен отдельный интеграционный набор.

## Вывод

Bottom-up дает раннюю локализацию ошибок хранения и передачи модели. Он полезен как основание тестовой пирамиды, однако сам по себе не подтверждает корректность внешнего API.
