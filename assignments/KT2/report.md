# КТ2. Микросервисы и REST API

**Цель:** Разработать REST-сервисы пользователей и заказов; проверить HTTP-взаимодействие Orders с Users, ошибки зависимости и время ответа.

**Ход тестирования:** Orders перед сохранением заказа выполняет GET /users/{user_id}. Users предоставляет POST /users и GET /users/{user_id}. Автотесты используют HTTPX ASGI transport, что позволяет связать оба приложения реальным HTTP-контрактом без сетевого запуска.

**Набор тестов:** `tests/test_microservices_integration.py`

## Сценарии и результаты

| Сценарий | Ожидаемый результат | Итог |
|---|---|---|
| Успешный межсервисный вызов | 201; заказ содержит профиль владельца | PASS |
| Users не содержит пользователя | 404; заказ не сохраняется | PASS |
| Users недоступен | 503; заказ не сохраняется | PASS |
| Задержка вызова Users | ответ менее 500 мс | PASS |
| Повторный email и невалидные данные | 409 и 422 соответственно | PASS |

## Результат

Все 9 API-тестов КТ2 прошли локально.

## Выявленные проблемы и ограничения

При настройке проекта обнаружено невалидное имя пакета в pyproject.toml: pip отклонил сборку. Имя исправлено на PEP 508-совместимое; установка и тестирование после исправления прошли.

## Вывод

Контракт между сервисами проверен вместе с позитивным и негативными ответами. In-memory хранилища предназначены для учебного стенда и очищаются после перезапуска.
