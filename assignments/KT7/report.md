# КТ7. Гибридное интеграционное тестирование

**Цель:** Проверить критические сценарии сразу на нескольких уровнях: REST API, бизнес-правило заказа, межсервисный клиент и репозиторий.

**Ход тестирования:** Совмещены нижнеуровневые тесты репозиториев, top-down проверки Orders controller с заглушкой и сквозные вызовы двух приложений через HTTPX. Это сочетает раннюю изоляцию с проверкой контрактов.

**Набор тестов:** `tests/test_bottom_up.py; tests/test_top_down.py; tests/test_microservices_integration.py`

## Сценарии и результаты

| Сценарий | Ожидаемый результат | Итог |
|---|---|---|
| Позитивный сквозной заказ | Users профиль получен, заказ создан и прочитан | PASS |
| Отсутствующий пользователь | заказ отклонен с 404 | PASS |
| Недоступная зависимость | возвращен 503, запись заказа отсутствует | PASS |
| Репозитории и контроллер | нижний и верхний уровни проверены раздельно | PASS |

## Результат

Все уровни проверены локально; в полном наборе 15 passed.

## Выявленные проблемы и ограничения

Разделение слоев локализует дефекты точнее Big Bang: repository, controller и сеть имеют самостоятельные проверки. Сквозная проверка при этом сохраняет доказательство работоспособности контракта между приложениями.

## Вывод

Гибридный подход дал наиболее сбалансированное покрытие проекта: критический пользовательский поток проверен насквозь, а нижние и верхние слои можно диагностировать отдельно.
