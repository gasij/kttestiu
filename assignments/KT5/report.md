# КТ5. Интеграционное тестирование сверху вниз

**Цель:** Начать с верхнего уровня Orders API и контроллера, затем подключить реальный сервис Users и нижние модули.

**Ход тестирования:** Шаг 1: тест контроллера заказа с AsyncMock-заглушкой UserClient. Шаг 2: проверка передачи user_id и отображения данных владельца. Шаг 3: подключение настоящего Users приложения через ASGI transport и проверка сквозного сценария.

**Набор тестов:** `tests/test_top_down.py; сквозной переход — tests/test_microservices_integration.py`

## Сценарии и результаты

| Сценарий | Ожидаемый результат | Итог |
|---|---|---|
| Контроллер + заглушка Users | 201; профиль добавлен в заказ | PASS |
| Заглушка сообщает 503 | ошибка возвращена клиенту, контроллер жив | PASS |
| Подключение реального Users API | создание заказа проходит через HTTP-контракт | PASS |

## Результат

2 top-down теста прошли; переход к реальному сервису прошел в сквозном API тесте.

## Выявленные проблемы и ограничения

Заглушка позволила проверить контроллер до подключения Users и отдельно зафиксировать передачу идентификатора. Она не проверяет сериализацию и реальный ответ Users; это покрыто следующим этапом.

## Вывод

Top-down удобен для ранней проверки пользовательского API и потока управления. В проекте он быстро выявил бы расхождения DTO на границе, но для достоверной интеграции заглушку необходимо заменить нижним модулем.
