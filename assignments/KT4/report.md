# КТ4. Интеграционное тестирование методом «Большого взрыва»

**Цель:** Объединить готовые модули Users, Orders, хранилища и HTTP-клиент на одном этапе и проверить систему как целое.

**Ход тестирования:** В один общий прогон включены оба API, репозитории и межсервисный HTTP-вызов. Сценарии не интегрируются по ступеням: сначала собран весь тестовый контур, затем запущен общий pytest suite.

**Набор тестов:** `Полный набор tests/`

## Сценарии и результаты

| Сценарий | Ожидаемый результат | Итог |
|---|---|---|
| Создание и чтение пользователей | API отвечает 201/200; неизвестный id дает 404 | PASS |
| Создание заказа с существующим пользователем | 201 и встроенные данные пользователя | PASS |
| Ошибки зависимого сервиса | 404 для неизвестного user; 503 при отказе соединения | PASS |
| Сквозной latency | вызов Users укладывается в 500 мс | PASS |
| Полная регрессия | 15 тестов после добавления всех уровней | PASS |

## Результат

Общий suite завершился без падений: 15 passed.

## Выявленные проблемы и ограничения

Метод подтвердил работоспособность интегрированного стенда, но первоначальная ошибка метаданных пакета блокировала весь запуск до выполнения тестов. Диагностика нашла причину в pyproject.toml; исправление сняло блокировку.

## Вывод

Big Bang уместен для небольшого учебного проекта из двух сервисов, но причины ранних интеграционных сбоев локализуются хуже. При росте системы нужны более ранние проверки контрактов и модулей.
