# КТ8. Непрерывное интеграционное тестирование

**Цель:** Автоматически запускать интеграционный набор при каждом push и pull request и сохранять машиночитаемый результат.

**Ход тестирования:** GitHub Actions workflow .github/workflows/tests.yml выбирает Python 3.12, устанавливает editable package с test extras, запускает pytest с coverage и формирует JUnit XML. XML публикуется как artifact даже при падении тестов.

**Набор тестов:** `Локальная проверка: python3 -m pytest -q`

## Сценарии и результаты

| Сценарий | Ожидаемый результат | Итог |
|---|---|---|
| Push / pull request | workflow запускается на обоих типах события | CONFIGURED |
| Установка зависимостей | pip устанавливает приложение и pytest extras | PASS |
| Локальный интеграционный прогон | 15 passed | PASS |
| Публикация результатов | JUnit XML загружается как artifact с if: always() | CONFIGURED |

## Результат

Локально выполнено 15 passed. Синтаксис workflow задан; удаленный запуск GitHub Actions не подтвержден из локальной рабочей среды.

## Выявленные проблемы и ограничения

Порог времени 500 мс проверяется интеграционным тестом локально и в CI. На загруженном runner возможна вариативность latency; при необходимости порог следует задавать исходя из SLA и распределения измерений.

## Вывод

CI обеспечивает повторяемый запуск после изменений и сохраняет JUnit результат. Для завершенной демонстрации удаленного CI нужен push проекта в GitHub и просмотр статуса workflow.
